DiskRepair

Diagnose, rescue and repair external storage on Windows: USB hard disks, flash drives, SD and microSD cards.

Overview

DiskRepair is a desktop tool (tkinter GUI plus a small command line) written in pure Python with no third-party dependencies. It talks to the device at the raw-sector level, so it can analyse and repair devices that Windows reports as RAW, "needs formatting", empty, or the wrong size.

Diagnose

Read-only inspection of partition tables, boot sectors, filesystems and surface health, ending in a plain-language verdict and an ordered repair plan.

Rescue

Image a failing device, copy files out with a built-in FAT/exFAT reader, or carve photos, videos and documents by signature.

Repair

Small undoable fixes first (boot sector, partition table), then CHKDSK, and finally erase-and-format as a last resort.

Test

Surface scan and a capacity/write test that exposes counterfeit cards and controllers that silently drop writes.

Requirements & start-up

  • Windows 10 or 11
  • Python 3.9 or newer (standard library only — nothing to install); pythonw must be on your PATH
  • Administrator rights — raw disk access is impossible without them

Starting the program

  1. Plug in the device you want to work on.
  2. Double-click DiskRepair.bat (or DiskRepair.pyw).
  3. Accept the Windows administrator (UAC) prompt. If you started without elevation, the program relaunches itself elevated; the header shows "Not running as administrator" in red when elevation is missing.
  4. Select your device in the External devices list on the left.
AntivirusSecurity software may flag raw-disk access. If DiskRepair is blocked, add an exclusion for the DiskRepair folder.

The safety guard

DiskRepair cannot open an internal disk — by design, with no override switch. The guard (diskrepair/safety.py) enforces:

  • Bus type. Only disks on the USB, SD, MMC or FireWire bus are accepted. SATA, NVMe, RAID, SAS, virtual disks and anything unrecognised are refused.
  • Protected disks. Any disk holding Windows, your user profile, the temp folder or DiskRepair itself is refused, even if it is on USB (e.g. Windows To Go).
  • Checked on the handle. The check runs on the very handle used for I/O, immediately before every operation, so a device swapped between "select" and "go" is caught.
  • Write fingerprint. Writing additionally requires the model | serial | size fingerprint of the device you selected, so a re-plugged device that took the same disk number is never written by mistake.
  • PowerShell too. The PowerShell commands used for formatting repeat the same check on their side.

Internal disks are counted in the header ("N internal disk(s) hidden and locked out") and are never listed as targets.

Recommended workflow

  1. Run the diagnosis. It is read-only and tells you which of the later steps apply.
  2. If the files matter, use Save rescue image and/or Copy files out before any repair.
  3. Apply small, undoable repairs the diagnosis suggests (boot sector, partition table).
  4. Last resort: if nothing else works and the data is safe or not needed, run the Capacity and write test, then Erase and format.
Rescue before you repairEvery repair step risks changing the device. If the device holds data you care about, copy it off first — especially if the device is clicking, disconnecting, or showing read errors.

Diagnosis tab

Click Run diagnosis (read-only). Nothing is written to the device. It checks:

  • Partition table (MBR / GPT / superfloppy / none) and each entry's sanity
  • Boot sectors and their backups; FAT, exFAT and NTFS structure
  • A sampled surface read to spot unreadable areas
  • A search for lost partitions that are missing from the table

Results appear as a list of findings with severity levels, each with detail text when selected:

LevelMeaning
CRITICALData or device is at immediate risk.
PROBLEMSomething is broken and needs repair.
WARNINGSuspicious but may be harmless.
NOTEInformational (e.g. an installer image that looks "unformatted" but is not damaged).
OKThe check passed.

Below the findings, Recommended steps, in order gives buttons for the repairs that apply. Show full technical report opens the complete text report.

Undo safety net

Before any boot-sector or partition-table write, the sectors being replaced are saved to DiskRepair-data\backups\ as a .bin plus a .json manifest (device fingerprint, LBA, note, time). Undo last change restores them. Writes are read back and verified; a write the device silently drops is reported as an error.

Erase and format

  1. Click Erase and format. A confirmation dialog shows exactly which device will be erased.
  2. Choose a filesystem:
    • FAT32 — cameras, consoles, car stereos (files up to 4 GB). DiskRepair has its own FAT32 formatter, so it works at any size up to 2 TiB, including cards above 32 GB that Windows refuses to format as FAT32.
    • exFAT — large files, cross-platform.
    • NTFS — Windows-only use.
    • Auto — FAT32 up to 32 GB, exFAT above.
  3. Optionally set a volume label, and tick Zero-fill the whole device first (slow; can revive some flash by forcing every block to be rewritten).
  4. Type ERASE to enable the button, then confirm. After formatting, a write-verification test confirms the device really stores data.

Partitions are aligned for flash (4 MiB up to 32 GB, 16 MiB above) and the scheme is MBR, or GPT for disks of 2 TiB and larger.

Recover data tab

All recovery actions are read-only on the device. Output is written to another disk — DiskRepair refuses a destination on the device being rescued and checks free space first.

ActionBest forNotes
Save rescue imageFailing or unstable devicesCopies every readable sector to an image file. Bad areas are skipped on the first pass, retried in small pieces, and left as zeros if still unreadable. Work on the image afterwards, sparing the device.
Copy files out (built-in reader)Volumes Windows won't mount (RAW)Reads FAT12/16/32 and exFAT directly, keeping names and folders. Tolerates a damaged FAT. Tick Also recover deleted files to include deleted entries.

Work from an imageUse Recover from a saved rescue image instead of the device (Browse… / Clear) to run Copy files out or Recover by signature against an image file. This lets you recover repeatedly without stressing a dying device.

Test tab

ActionWhat it does
Full surface scan Read-onlyReads the whole device and builds a map of unreadable areas.
Capacity and write test Writes test blocks, then restores themWrites marker blocks across the whole address space on a power-of-two grid, reads them all back, then puts the original contents back. Detects:
  • "Limbo" fakes — writes beyond the real capacity are dropped.
  • "Wraparound" fakes — high address bits are ignored so the space repeats.
  • Stuck controllers — accept writes without storing them.
The result reports the real usable size. A Thorough option probes every 256 MB instead of 32 probes in total.
Fake-capacity cardsNo format fixes a counterfeit card. Format it with a size limit (CLI --limit-bytes) only if you accept using the real part — never trust it for important data.

Common scenarios

"You need to format the disk before you can use it" (RAW)

  1. Run diagnosis. If it reports a damaged boot sector with an intact backup, choose Restore boot sector from backup.
  2. If files matter and that fails, use Copy files out (works on RAW volumes).

Device shows as empty / wrong size / "unallocated"

  1. Run diagnosis; if a lost filesystem is found, Rebuild partition table.
  2. If it isn't found quickly, run Deep search for lost partitions first.

Read-only / "disk is write protected"

  1. Check the lock switch on the SD adapter.
  2. Run Clear write protection. If it stays locked, the controller has gone into end-of-life read-only mode — copy the data off and replace the device.

Card holds fewer files than expected / files vanish / "corrupt" after a few GB

  1. Run the Capacity and write test. A fake-capacity or dropping controller explains it.

Photos from a card that won't open at all

  1. Save rescue image, then Recover files by signature from that image.

Command line

The GUI is the main interface; the CLI is for scripting and support. Disk commands need an elevated prompt.

python -m diskrepair list
python -m diskrepair diagnose 1                    # disk number
python -m diskrepair diagnose rescue.img           # or a saved image file
python -m diskrepair diagnose 1 --deep --json report.json --hexdump
python -m diskrepair captest 1 --serial ABC123 [--thorough] [--json out.json]
python -m diskrepair format  1 --serial ABC123 --erase-all-data \
        [--fs auto|fat32|exfat|ntfs] [--label NAME] [--zero-fill] [--limit-bytes N]
python -m diskrepair gui                           # the default
CommandPurpose
listExternal disks with their volumes, plus the count of protected internal disks and any device problems Windows reports.
diagnoseRead-only diagnosis of a disk number or an image file. --deep adds a deep partition search; --json FILE saves the report; --hexdump appends the first sector.
captestCapacity/write test. Needs --serial as shown by list; the disk must be named by number and serial.
formatErase and format. Refuses to run without --erase-all-data and a matching --serial. --limit-bytes confines the partition to the first N bytes (fake-capacity cards).

Where files go

Everything DiskRepair produces is stored in a DiskRepair-data\ folder next to the program, and is never allowed onto the device being rescued.

FolderContents
DiskRepair-data\recovered\Files copied out or carved, in one subfolder per run (e.g. microsd-20261110-130015\fat32-volume\…).
DiskRepair-data\backups\Saved sectors (.bin + .json) used by Undo, and by the capacity test to restore data.
DiskRepair-data\logs\Daily log files diskrepair-YYYYMMDD.log.

Rescue images (diskN-YYYYMMDD-HHMMSS.img) default to DiskRepair-data\images\, but a Save dialog lets you choose any folder on another disk. Images need as much free space as the device is large; the tool checks before starting.

What software cannot fix

  • A device that never appears in the list — it isn't answering on the bus (dead controller, broken connector). Try another port, cable or card reader.
  • A reader that reports "no media" / zero capacity with the card inserted.
  • Flash that has locked itself read-only at end of life (the write test reports this).
  • Counterfeit capacity. The test shows the real size; the card cannot be trusted.
  • Physically unreadable sectors. They can be skipped and mapped, not healed.

Architecture

Source lives in the diskrepair package. The GUI only renders; all disk work runs on a worker thread and reports through a Task object (progress, log, cancel).

ModuleRole

winapi.pyWindows API wrappers (handles, storage descriptors, geometry, elevation checks) via ctypes.
blockdev.pyPhysicalDevice (guarded, locks volumes) and ImageDevice (file-backed, used for rescued images and tests).

layout.pyParse, validate and build MBR, GPT, and FAT/exFAT/NTFS boot sectors.
diagnose.pyTurns structure checks into findings, a verdict and an ordered repair plan.
scan.pyLost-partition search and surface (bad-sector) scans.
repair.pyBoot-sector restore, partition-table rebuild, undo, erase/format, write-protection clearing, CHKDSK.
fat32fmt.pyOwn FAT32 formatter for any size up to 2 TiB.
fsread.pyBuilt-in read-only FAT12/16/32 and exFAT readers.
rescue.pyResilient imaging and signature-based carving.
captest.pyCapacity / write-retention test.
task.pyProgress, logging and cancellation plumbing.
cli.py, gui.py, __main__.pyFront ends. DiskRepair.pyw / DiskRepair.bat launch the GUI.

Running the tests

python -m unittest discover tests -v

The suite builds simulated disk images — lost partition table, destroyed boot sector, bad sectors, fake capacity, stuck controller — and never writes to a physical disk. It covers the safety guard, format and diagnosis, repair and undo, data recovery (FAT32/exFAT extraction, carving, imaging, surface scan) and the capacity test.
